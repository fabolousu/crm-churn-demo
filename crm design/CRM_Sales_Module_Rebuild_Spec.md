# CRM Sales Module — Rebuild Specification for an AI Agent

> **Source:** "Manuale Operativo Modulo Sales" (internal user manual, updated 08/2024) for the *CRM CCIAA – PROMOS* instance of Microsoft Dynamics 365 used by Promos Italia.
> **Purpose:** This document lists every feature, entity, field, status, view and workflow that can be identified in the manual, including from its screenshots. An AI coding agent should be able to rebuild a functionally equivalent platform from scratch using it.
> **Language note:** The original UI is in **Italian**. Italian labels are given in `code` next to each English description, and the rebuilt UI should keep them as its default locale (i18n-ready).
> **Legend:** Items marked **[inferred]** are not stated explicitly but follow from screenshots or standard behaviour of the source system. Items marked **[explicit]** are rules the manual states directly. Everything else is visible in the manual.

## 0. Product summary

A B2B CRM for a chamber-of-commerce agency that promotes **initiatives** (`Iniziative`) to companies: trade missions, business-matching events, webinars, courses, consulting services and digital buyer platforms (e.g. *InBuyer*). It has five building blocks:

1. **Master data** (`Anagrafiche`): Companies (`Aziende`), Contacts (`Contatti`), and the many-to-many **Company–Contact relationship** (`Relazioni Aziende-Contatti`).
2. **Initiatives catalogue** (`Anagrafica Iniziative`).
3. **Expressions of interest** (`Manifestazioni di Interesse`). These are generated automatically from marketing e-mail campaigns (DEM) and registration forms.
4. **Leads.** A lead is one interest of one contact/company in **one** initiative. It has a working status lifecycle and an owner, and every interaction is logged on its activity timeline.
5. **Productivity layer:** configurable list views, column and filter editing, saved personal views, bulk edit, Excel export/import, e-mail from the CRM with signatures, notifications, and assignment.

The core user is the **initiative owner** (`Referente dell'iniziativa`, also called the lead owner or `Proprietario`). This person receives leads, contacts the company (by phone, e-mail or meeting) and moves the lead through its statuses until it closes.

## 1. Glossary (domain definitions) [explicit]

| Term (IT) | Term (EN) | Definition |
|---|---|---|
| `Lead` | Lead | The interest of a **contact associated with a company** in **one specific** initiative or service. A lead is **unique per initiative/service**. One contact can have many leads, one for each initiative. |
| `Manifestazione di interesse` | Expression of interest | A contact's request (on behalf of a company) **to be re-contacted** about an initiative. It is generated by targeted promotional actions (DEM, i.e. direct e-mail marketing). **It automatically creates a lead**, which is assigned to the initiative's owner. |
| `Iscrizione all'evento` | Event registration | Registering for an event automatically creates a lead that is **already closed**, with status `Iscritto all'evento`. It is closed because the owner has nothing more to do with it. This applies **only to events**. |
| `Iscrizione InBuyer` | InBuyer platform sign-up | A different use case: it creates a lead that **must be worked** and eventually moved to `Servizio concluso`. |
| `Referente dell'iniziativa` / `Proprietario` | Initiative owner / record owner | The user responsible for the initiative. Leads for that initiative are assigned to this user. |
| `Stato di lavorazione` | Working status | The lead's pipeline stage. Each status is either *open* or *closed*. |
| `Sequenza temporale` / `Timeline` | Activity timeline | The chronological log of all activities on a record: e-mails, notes, appointments, calls, tasks and system e-mails. |
| `Vista` / `Visualizzazione` | View | A saved list configuration: columns, filters and sort order. Views are either *system* views or *personal* views. |
| `Bacino di utenza` | Target audience | A filtered list of companies/contacts built with a custom view, e.g. for recall campaigns. |

## 4. Lead working-status model (`Stato lavorazione`)

### 4.1 Status catalogue

| Status (IT) | Category | Meaning | Who sets it |
|---|---|---|---|
| `Nuovo` | Open | **Default for leads created manually** | System (manual create) |
| `Interessato` | Open | Default for leads from an **expression of interest** or a **service request**. Also used for manual leads. The owner must check that the interest is real | System (auto) / user |
| `Da contattare` | Open | The user plans to contact the lead | User |
| `In attesa di riscontro` | Open | Contacted; waiting for a reply | User |
| `Prefattibilità negativa` | Closed | The company lacks the requirements | User |
| `Nessuna risposta` | Closed | Contacted, never answered | User |
| `Non interessato` | Closed | Final: not interested in *this* initiative (a new lead can still be created for a different one) | User |
| `Iscritto all'evento` | Closed | Registered for an event, course or service **before** taking part or receiving it. **Auto-set by event registrations** | System / user |
| `Servizio concluso` | Closed | The service was delivered, or the company **actually attended** the webinar/course. If it did not attend, the lead stays `Iscritto all'evento` | User |
| `Contratto concluso` | Closed | The company formally joined the initiative (contract signed) | User |

**Legacy/extra statuses** appear in the bulk-edit dropdown and must also be supported: `Interessato InBuyer` (open: InBuyer platform sign-up), `Concluso` (closed), `Da richiamare` (open: call back), `Perso` (closed: lost). Mark them `is_legacy = true` so admins can hide them from new records.

Implement statuses as a **configurable table** (code, label_it, label_en, category open/closed, sort order, is_default_manual, is_default_auto, is_legacy, active), not as a hard-coded enum.

### 4.2 Allowed transitions
The manual sets no strict transition rules: any status can be chosen from the dropdown. Implement **free transitions** by default and add these hooks:
- Moving to a **closed** status sets `Data chiusura = now()` and moves the lead from "open" views to "closed" views.
- Moving from closed back to open clears `Data chiusura` [inferred].
- Typical happy paths:
  - Interest → `Interessato` → `Da contattare` → `In attesa di riscontro` → `Iscritto all'evento` → `Servizio concluso`.
  - Interest → `Interessato` → … → `Contratto concluso`.
  - InBuyer → `Interessato InBuyer` → `Servizio concluso`.
- Example from the manual: a lead from an event expression of interest that registers after follow-up goes from `Interessato` to `Iscritto all'evento`.

### 4.3 Changing the status
- **Single record:** on the lead form, open the header flyout (chevron next to the owner name), choose a new `Stato lavorazione`, then `Salva`.
- **Bulk:** see §7.6.

## 5. Lead workflows

### 5.1 Automatic lead creation (integrations) [explicit]
1. **From an expression of interest (DEM campaign response / web form):**
   - Create a `Manifestazione di Interesse`, resolving or creating the Contatto and Azienda [inferred].
   - Automatically create a Lead with `Stato = Interessato`, `Fonte = Manifestazione di interesse`, `Anagrafica interesse = initiative`, `Proprietario = initiative's 1° Referente`. Copy `Tipo interesse` and `Richieste del Contatto/Cliente`, link `Manifestazione interesse origine`, and auto-generate `Argomento`.
   - **Send a notification e-mail** to the owner from a no-reply address (`crm-noreply@…`). Subject: "Creazione Lead - Interesse per Iniziativa - <name>". Body: "Gent. utente, è stato creato un nuovo Lead a seguito di una manifestazione di interesse…" ("Dear user, a new lead has been created following an expression of interest…"). It must contain a **deep link to the lead record**. The e-mail also appears on the lead timeline as a closed activity.
2. **From an event registration:** create a Lead with `Stato = Iscritto all'evento` (closed), so it needs no follow-up.
3. **From an InBuyer platform sign-up:** create a Lead (`Interessato InBuyer` / `Interessato`) that stays open until the owner sets `Servizio concluso`.
4. **From a service request** (`richiesta di adesione al servizio`): create a Lead with `Stato = Interessato`.

Expose these as **API endpoints / webhooks** (e.g. `POST /api/intake/interest`, `/api/intake/event-registration`, `/api/intake/inbuyer-signup`) with idempotency keys. Before creating, check the lead-uniqueness rule (§3.6); if a lead already exists, attach the new expression of interest to it [inferred].

### 5.2 Viewing and working your leads
- `Lead` in the sitemap opens the default view **`Lead personali aperti`** (my open leads). The user's personal default view overrides it (§7.2).
- Double-click the `Argomento` cell to open a lead.
- From the timeline, use `+` to add an E-mail, Nota, Appuntamento, Telefonata or Attività (§6).

### 5.3 Manual lead creation (three entry points) [explicit]
**A. From a Contact.** Open `Contatti` and search `*Nome Cognome` (the leading `*` makes it a contains-search). Open the contact, go to the `Sales` tab, and click `+ Nuovo elemento Lead`.
- The new lead has `Contatto` prefilled and `Stato = Nuovo`, and its owner is the current user.
- The user must pick `Anagrafica interesse` (required), then save.
- **Company auto-link rule:** if the contact has exactly **one** company relationship, `Azienda` is filled automatically. If it has **several**, the user opens the company lookup (Enter key) and chooses one; the lookup is filtered to that contact's related companies [inferred].

**B. From a Company.** Same flow from the `Aziende` list and the company's `Sales` tab. `Azienda` is prefilled. **`Contatto` is still required**, and its lookup should be filtered to the company's contacts [inferred].

**C. From an Initiative.** Open `Anagr. Iniziative` (or search for it), then the `Lead` tab, then `+ Nuovo elemento Lead`. `Anagrafica interesse` is prefilled. The user sets the status and picks the company and contact with type-ahead lookups.

**Rule [explicit]:** the **timeline only becomes available after the first save**. Before that, show "Save the record to add activities".

### 5.4 Reassigning a lead to a colleague
Open the lead, open the header flyout, clear `Proprietario`, type the new user's name (type-ahead user lookup), then `Salva`. A command-bar `Assegna` button (single or bulk) does the same through an assign dialog.
**[inferred]** Notify the new owner (same e-mail template as §5.1, with "assigned to you") and record the change in the audit log.

## 7. Views, columns, filters, search (configurable lists)

Custom views can be built for **every entity**: Companies, Contacts, Company–Contact relationships, Leads, and so on [explicit].

### 7.1 System views (Lead)
| View | Definition |
|---|---|
| `Lead personali aperti` | owner = current user AND status ∈ open (**system default**) |
| `Tutti i lead` | all leads the user may read |
| `Lead aperti` | status ∈ open |
| `Lead chiusi` | status ∈ closed |
| `Lead conclusi con esito positivo` | status ∈ {Servizio concluso, Contratto concluso, Iscritto all'evento [inferred]} |
| `Lead personali` | owner = current user |
| `Lead personali chiusi` | owner = current user AND status ∈ closed |

Default columns for the Lead views: Argomento, Contatto, Azienda, (1° Macro Settore), Anagrafica interesse, Proprietario, Stato lavorazione, Data creazione, Data modifica ↓.

Other default views: `Tutti i contatti` (Nome completo ↑, E-mail, Telefono, Nazionalità, Maturità anagrafica, Completezza anagrafica, Data modifica ↓); `Tutte le aziende` (Denominazione ↑, Codice Fiscale, Partita IVA, Provincia, 1° Macro Settore, Tipologia, Maturità); `Tutte le Relazioni Azienda Contatto`; `Anagrafiche Iniziative con codici`.

### 7.2 View selector menu
- Grouped list: **`Visualizzazioni personali`** (personal views, user icon, e.g. "Tutti i lead con iniziative con date") and **`Visualizzazioni di sistema`**. A `Predefinito` badge marks the default.
- `Cerca visualizzazioni`: search inside the list.
- Actions:
  - `Salva modifiche alla visualizzazione corrente` (save changes to the current view)
  - **`Salva come nuova visualizzazione`** (save as a new view: prompts for name and description)
  - `Reimposta visualizzazione predefinita` (reset)
  - `Imposta visualizzazione corrente come predefinita personale` (set as my default)
  - `Gestisci e condividi le visualizzazioni` (manage and share: rename, delete, share with users/teams)
- An **unsaved, modified view** gets an asterisk after its title (`Tutte le Relazioni Azienda Contatto*`). **Unsaved changes are lost on navigation [explicit].** The rebuild should keep this behaviour and warn before leaving with unsaved changes.
- Saved personal views are private to the creator unless shared. They stay valid across platform updates [explicit].

### 7.3 Edit columns panel (`Modifica colonne`)
- Side panel `Modifica colonne: <entity>` lists the current columns.
- `+ Aggiungi colonne` opens a picker with two tabs:
  - **Current entity** fields (e.g. "Relazione Azienda Contatto").
  - **`Elementi correlati`** (related entities): expandable relations such as Autore, Autore modifica, **Azienda (Azienda)**, **Contatto (Contatto)**, Proprietario, Team proprietario, Utente proprietario. Expanding one lists the related entity's fields, labelled `<Field> (<Entity>)`, e.g. `Provincia (Azienda)`, `1° Macro Settore di attività (Azienda)`, `Principali aree o Paesi di Export (Azienda)`.
  - A search box and a type filter (`Tutte` / by data type). Each field shows its type icon.
  - A selected field **disappears from the picker** and is added to the view. `Chiuso` closes the picker.
- Columns can be **reordered by drag and drop**. Columns can be removed and resized [inferred].
- `Reimposta impostazione predefinita` restores the default columns.
- `Invia domanda` (apply) and `Annullamento` (cancel).
- **Known quirk [explicit]:** in the source system, filters applied before adding columns are lost. The rebuild **must not** have this bug; keep filters when columns change.

### 7.4 Column header menu and filters
- Per-column menu: `Ordina da A a Z`, `Ordina da Z ad A`, **`Filtra per`**.
- The `Filtra per` dialog has an operator dropdown and a value picker.
  - Operators by type: text = equals, does not equal, contains, does not contain, begins with, ends with, contains data, does not contain data. Lookup/choice = equals (multi-select from a list), does not equal, contains data, does not contain data. Date = on, after, before, last X days, this month… Number = =, ≠, >, <, between.
  - Value picker for lookups: a searchable list (e.g. provinces PISA … RAVENNA …), multi-select (example: Provincia ∈ {RAVENNA, FERRARA} AND 1° Macro Settore = Agroalimentare).
  - Buttons: `Applica`, `Cancella` (clear).
- A filtered column shows a funnel icon in its header.
- **`Modifica filtri`** opens an advanced filter builder: AND/OR groups, conditions on the entity and its related entities.
- Filters, columns and sort order together define a view and are saved with it.

### 7.5 Search
- **Quick find** box per view (`Cerca in questa vista`). It matches the start of indexed text fields by default. **A leading `*` wildcard turns it into a contains-search** (e.g. `*Giuseppe Molinari`, `*moltren`) [explicit]. Clear with ✕.
- **Global search** in the top bar searches across entities.
- Lookup fields support type-ahead and an "advanced lookup".

### 7.6 Bulk edit (`Modifica` on multiple selected rows) [explicit]
- Select rows with checkboxes, then `Modifica` opens a dialog **"Modifica N record"** ("Immetti le modifiche nei campi da modificare": enter changes in the fields to update).
- The dialog shows the entity form (tabs `Generale`, `Dati Amministrativi`, `Intestazione`) with every field empty or set to `--Seleziona--`. Only fields the user changes are written.
- Typical use: set `Stato lavorazione` for many leads at once.
- `Salva` / `Annulla`. Apply the update as one batch with per-record validation and a result summary.

### 7.7 Charts, dashboards, reports
- `Mostra grafico` opens a chart pane beside the grid, based on the current view (e.g. leads by status, by owner).
- `Dashboard` (sitemap) holds personal and system dashboards built from charts and lists. `Apri dashboard` is in the overflow menu.
- `Esegui report` runs predefined reports on the selected records or the view.
- `Mostra questa visualizzazione` shows an embedded BI visualisation of the view (Power BI equivalent; optional).

## 8. Import and export

### 8.1 Export a view to Excel [explicit]
- From any list, the `⋮` overflow menu has **`Esporta in Excel`**. It produces an `.xlsx` with **exactly the records and columns of the current view**: all pages and all filters, not just the visible page. The file is downloaded to the browser's download folder.
- From an Initiative's `Lead` sub-grid, `⋮` → **`Esporta Lead`** exports only that initiative's leads.
- Also in the menu:
  - **`Modelli di Excel`**: Excel templates, i.e. predefined export layouts the user can pick.
  - **`Importa da Excel`**: bulk import or update with column mapping, validation, duplicate detection and an error report [inferred details].
- Respect security: export only records and fields the user can read [inferred].

## 10. Security and ownership [mostly inferred]
- **Users** belong to **business units** and **teams** (e.g. *Team Anagrafiche Promos* owns company and contact master data).
- Role-based access per entity and privilege (Create, Read, Write, Delete, Append, Assign, Share), scoped to User, Team, Business Unit or Organisation.
- Initiative owners see and edit their own leads; managers see everything.
- Master data (companies, contacts) is owned by a central data team, and other users may have read-only access to some locked fields (Codice Fiscale, E-mail).
- Audit log of field changes (status, owner).
- Each licensed user's default lead view shows only **their own** open leads [explicit].

## 14. Non-functional requirements
- **Locale:** Italian UI by default, EU date format `dd/mm/yyyy HH:mm`, Europe/Rome time zone, and i18n-ready (all labels in resource files).
- **Scale:** contacts and relationships above 5,000 records (counts display "5000+"); about 1,200 initiatives; leads in the thousands per user group. Lists must paginate on the server and filter and sort efficiently.
- **Deep links:** every record has a stable URL (`/app/{entity}/{id}`) and every view has one (`/app/{entity}?view={viewId}`).
- **GDPR:** contact consents (the manual mentions a view "Contatti … + tipo informativa e consenso", i.e. contacts plus privacy-notice type and consent). Add consent fields to the Contact: privacy notice type, consent flags, date. Support data export and erasure for a contact.
- **Auditability:** full audit trail on Lead status and owner changes.
- **Integrations:** inbound webhooks for expressions of interest, event registrations and InBuyer; outbound e-mail with mailbox sync; Excel import/export; automation hooks (`Flusso`).
- **Migration:** fields `Note migrate` and the topic "Iscrizione migrata" show there was a legacy data migration, so provide a CSV/Excel import that keeps the original creation dates.

## 15. Suggested implementation plan for the agent

> Use any modern stack. A reasonable default: **PostgreSQL + a TypeScript backend (NestJS/Fastify) + a React frontend (data grid such as AG Grid or TanStack Table) + a job queue for e-mails and imports.** Use a metadata-driven design so views, columns and filters are generic across entities.

1. **Metadata layer:** an entity/field registry (name, label_it, type, required, read-only, lookup target, searchable). The generic grid, forms, column picker, filter builder and Excel export all read from it.
2. **Core entities and relations** (§3) with migrations and seed data: provinces, macro sectors and sectors, job positions, maturity, lead statuses (§4.1), activity lines, initiative types.
3. **Auth and RBAC, teams, ownership, sharing** (§10).
4. **Generic list engine:** server-side query builder (columns across related entities, filters with AND/OR, sort, pagination, `*` contains-search). Saved views (system/personal/shared, default per user), with an unsaved-changes indicator.
5. **Generic form engine:** tabs, sections, header fields, quick-view panels, sub-grids, required and locked fields.
6. **Lead logic:** auto title, uniqueness, company auto-link, open/closed categories, closing date, owner defaults.
7. **Timeline and activities:** e-mail composer with templates, signatures, attachments, and send with mailbox sync.
8. **Intake APIs and automations** (§5.1) plus the notification e-mails.
9. **Bulk edit, assign, share, delete, deactivate.**
10. **Excel export** (full view), Excel templates, Excel import.
11. **Charts, dashboards, reports** (basic aggregations by status, owner, initiative and province).
12. **Personal settings** (signatures, templates, preferences).
